# Kezoi premium WhatsApp Flow — Data Exchange contracts

Implementation date: 14 October 2026. Endpoint: `POST /api/meta/flows/booking`.

All requests and responses use the existing Meta RSA-OAEP/AES-GCM envelope. The JSON below is the decrypted content. The published Flow was not changed. These contracts are for a draft Flow that is wired to the existing endpoint after owner approval.

## Shared rules

- Dates are `YYYY-MM-DD`; checkout is exclusive.
- `property_id` is the database property ID.
- Guest fields are whole-number strings or numbers: `adults >= 1`, `children >= 0`, `infants >= 0`, `pets >= 0`.
- Capacity is `adults + children + infants`. Pricing occupancy is `adults + children`.
- Every exchange reads the website PostgreSQL data. The Flow JSON must contain no prices, availability, capacity, or image bytes.
- A screen validation failure stays on the requesting screen and returns `{ "error_message": "..." }`.
- `flow_token` is used to derive a non-PII, stable idempotency key at final submission.

## Selected-property entry screens

The carousel passes only backend identifiers; it does not pass property content, availability, pricing, image bytes, or GST.

### View Stay

Initial screen: `VIEW_STAY_ENTRY`

```json
{"property_id":"1","property_code":"TG-0001","entry_intent":"view_stay"}
```

The entry screen sends a `data_exchange` request with the same fields. The backend reads the active property and responds with `PROPERTY_DETAILS`, including description, location, amenities, `amenities_text`, capacity and up to three active gallery images.

### Reserve

Initial screen: `RESERVE_ENTRY`

```json
{"property_id":"1","property_code":"TG-0001","entry_intent":"reserve"}
```

The entry screen sends a `data_exchange` request with the same fields. The backend reads the property and live unavailable dates and responds with `CALENDAR`. Dates, guests, price and GST continue through the existing backend-owned transitions.

Meta `navigate` can provide initial screen data without requiring n8n to duplicate property content, but dynamic content is not fetched until an action reaches the Data Exchange endpoint. The two lightweight entry screens therefore require one guest tap. If the installed Meta client supplies the same selected-property data in an encrypted `INIT` request, the backend also routes `INIT` directly to `PROPERTY_DETAILS` or `CALENDAR`; this optimization must not be claimed until verified in Meta's client/tester.

## 1. `BOOKING_DETAILS` → `PROPERTY_SELECTION`

Request data:

```json
{"check_in":"2026-11-01","check_out":"2026-11-03","guests":"2","children":"0","infants":"0","pets":"0"}
```

Response data:

```json
{
  "check_in":"2026-11-01","check_out":"2026-11-03","adults":"2",
  "properties":[{"id":"1","title":"<database name>","description":"3 bedrooms | 3 bathrooms | INR 23600"}],
  "no_properties_available":false,"quote_generated_at":"<ISO timestamp>"
}
```

The list includes only active, capacity-compatible, available properties. The amount is generated by the backend quotation service.

## 2. `PROPERTY_SELECTION` → `PROPERTY_DETAILS`

Request data adds `property_id`.

Response data:

```json
{
  "property_id":"1","property_name":"<database name>",
  "property_description":"<admin public_description>",
  "property_location":"<admin public_location>",
  "amenities":["Wi-Fi","Kitchen"],"amenities_text":"Wi-Fi • Kitchen","max_guests":8,
  "gallery":[{"src":"<raw JPEG/PNG base64>","alt-text":"Living room"}]
}
```

The draft Flow `ImageCarousel.images` binds to `${data.gallery}`. The backend returns at most three active photos, ordered by cover first, then `display_order`, then ID. Admin writes are authenticated at:

- `POST /api/operations/photos/marketing`
- `GET /api/operations/photos/marketing/property/{propertyId}`
- `PATCH /api/operations/photos/marketing/{id}`

The admin API accepts either JPEG/PNG base64 or an HTTPS URL on an approved property-image host. Existing WebP S3 images are downloaded by exact URL and converted to JPEG. URL-derived images use a conservative 240 KB per-image budget so three base64 images plus the rest of the encrypted response remain within Meta's 1 MB data-channel payload limit. `image_url` is retained for provenance, but the runtime Flow receives embedded base64, not a URL. Changing an admin gallery URL regenerates its Meta image data.

## 3. `PROPERTY_DETAILS` → `CALENDAR`

Request data carries `property_id` and prior selections.

Response data:

```json
{"unavailable_dates":["2026-11-10","2026-11-11"],"calendar_refreshed_at":"<ISO timestamp>"}
```

The draft `CalendarPicker` binds its unavailable-date property to `${data.unavailable_dates}`. Dates combine property blocks and `HOLD`, `CONFIRMED`, and `CHECKED_IN` bookings. Checkout dates remain selectable.

## 4. `CALENDAR` → `GUEST_SELECTION`

Request data adds the selected `check_in` and `check_out`. The backend reloads unavailable dates and rejects any overlap.

Response data:

```json
{"property_id":"1","check_in":"2026-11-01","check_out":"2026-11-03","max_guests":8}
```

## 5. `GUEST_SELECTION` → `LIVE_QUOTE`

Request data adds `adults`, `children`, `infants`, and `pets`.

Response data:

```json
{
  "property_name":"<database name>","nights":2,"currency":"INR",
  "base_amount":20000,"extra_guests":0,"extra_guest_amount":0,
  "taxable_amount":20000,"gst_rate":18,"cgst_amount":1800,
  "sgst_amount":1800,"gst_amount":3600,"total_amount":23600,
  "quote_generated_at":"<ISO timestamp>"
}
```

Capacity, availability, base price, included guests, extra-guest price, GST settings, and totals are all re-read/calculated by the backend.

## 6. `LIVE_QUOTE` → `GUEST_DETAILS`

Carries the prior server response and selections without creating a hold, enquiry, booking, or payment.

## 7. `GUEST_DETAILS` → `BOOKING_REVIEW`

Request data adds:

```json
{"guest_name":"Test Guest","guest_email":"test@example.com","whatsapp_number":"+919876543210","country_code":"IN","special_requests":"Optional"}
```

The backend validates email/phone, normalizes the phone number, and performs another availability/capacity/price refresh. Response data includes all prior fields plus:

```json
{"property_name":"<database name>","quote":{"total_amount":23600,"gst_amount":3600},"quote_generated_at":"<ISO timestamp>"}
```

`quote` is the complete backend quotation object, including base, extra-guest, taxable, CGST, SGST, GST, and total fields.

## 8. `BOOKING_REVIEW` → `ENQUIRY_CREATED`

The request contains the complete reviewed data and the top-level Meta `flow_token`. In one database transaction the backend:

1. locks the property;
2. rechecks capacity and availability;
3. recalculates the quotation and GST;
4. creates/reuses the guest;
5. creates exactly one idempotent `WHATSAPP` enquiry with status `NEW` and document status `PENDING`.

Response data:

```json
{
  "enquiry_reference":"APP-42","enquiry_status":"NEW","payment_status":"NOT_STARTED",
  "continuation_type":"IDENTITY_DOCUMENT_UPLOAD",
  "continuation_url":"<signed website handoff URL>","replayed":false,
  "message":"Enquiry created. No booking or payment has been confirmed."
}
```

The URL is generated only in the encrypted response and expires after 24 hours. It is an identity-document handoff, not proof of payment. No booking is confirmed and the internal payment API is never called.

## Meta image binding

Flow JSON 7.3 supports `ImageCarousel` (introduced in 7.1). The component consumes one to three `{src, alt-text}` items where `src` is raw JPEG/PNG base64. A draft screen should declare `gallery` as an array data field and bind `ImageCarousel.images` to `${data.gallery}`. Runtime HTTP image URLs are not used.
